# Как объяснить проект на интервью

Я сделал сервис фичефлагов и Python SDK с локальным снимком. Изменение конфигурации, номер версии и аудит сохраняются вместе. SDK узнаёт о новой версии через SSE, затем загружает снимок; периодический опрос страхует потерянное уведомление.

Для процентного включения я использовал SHA-256 со стабильной солью флага. У пользователя остаётся прежний bucket после перезапуска и смены процента. Поэтому группа на 1% входит в группу на 10%, а та — в 100%. Для организаций можно переключить единицу распределения на organization_id.

Самый важный компромисс — поведение при недоступности сервера. Некоторое время продолжаем использовать кеш, но после max_stale возвращаем false. Мгновенное отключение во время сетевого разрыва невозможно гарантировать. В ответе есть причина и версия, чтобы такое решение можно было объяснить.

На показе: `make smoke` для вложенных групп и быстрого выключения, затем `make recovery` для кеша и восстановления. SDK-ключ не даёт права редактировать флаги, а сам флаг не заменяет проверку доступа к данным.

Дальнейшая работа для команды: командные роли, отдельный лёгкий пакет SDK, метрики его свежести, журнал доставки конфигураций и нагрузочные проверки нескольких API-реплик.
