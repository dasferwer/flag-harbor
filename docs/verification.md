## Что проверяли

Проверены стабильность распределения после смены Python hash seed, вложенность групп, таргетинг организаций и групп, приоритет отключения и исключений. Из десяти конкурентных изменений с одним ETag принято одно; сбой записи аудита откатывает изменение флага и revision.

SDK-тесты проверяют локальные решения без HTTP на каждый вызов, истечение кеша, обновление через 304, немедленную очистку после 401, отказ от повреждённой или регрессирующей версии и изоляцию окружений. Живой сценарий подтвердил SSE-отключение и отзыв ключа.

После SIGKILL API SDK некоторое время использовал кеш, затем вернул `false`. После восстановления сервера настройки сохранились и снова загрузились. Для быстрого сценария использовались max_stale=2 секунды и polling=0,2 секунды; обычные значения — 30 и 2 секунды соответственно.

## Локальный замер SDK

На 10 000 идентификаторах группы составили [115, 1031, 10000]; они вложены друг в друга. Точное число пользователей на 1% не обязано равняться 100: процент задаёт порог хеша, а не квоту мест.

В одном прогоне SSE-отключение заняло 29.31 мс при polling=30 секунд. Для 10 000 синхронных проверок одного флага p50 = 4.58 мкс, p95 = 11.96 мкс. Время включает валидацию контекста и создание результата. Это один локальный прогон в Docker, Python 3.12.14, aarch64, без параллельных запросов к evaluate. Эти числа не являются SLA или измерением производительности кластера.

## Повторить

```bash
make check
make test
make up
make smoke
make recovery
docker compose exec -T api python scripts/seed.py
docker compose exec -T api python scripts/seed.py
```

Тестовая база отделена от пользовательской и остановлена после проверки. Рабочие контейнеры оставлены запущенными. В репозитории есть GitHub Actions workflow для этих же основных проверок. Этот отчёт описывает локальный прогон; текущий статус удалённых проверок доступен в [GitHub Actions](https://github.com/dasferwer/flag-harbor/actions).
