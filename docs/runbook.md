# Работа с API

`make up` поднимает PostgreSQL, выполняет Alembic и seed, затем API на 8190. Все опубликованные порты ограничены loopback. `/health` проверяет базу, `/metrics` содержит HTTP-метрики. Demo-пароль и JWT-секрет относятся к локальному запуску; `.env.example` показывает настройку собственного секрета.

## Управление флагом

1. Зарегистрироваться и войти через `/auth/register` и `/auth/login`, сохранить JWT.
2. `POST /environments` с `{"name":"staging"}` создаёт окружение и однократно отдаёт `sdk_key`.
3. `GET /environments/{id}` возвращает `ETag`. Передать его целиком в `If-Match` при `PUT /environments/{id}/flags/search` с телом `{"enabled":true,"rollout_bps":100,"organizations":[],"groups":[],"excluded_users":[],"stickiness":"user"}`.
4. Повторить чтение ETag и изменить `rollout_bps` на 1000, затем 10000. `PUT` заменяет все редактируемые правила флага; пропущенные поля получают значения по умолчанию.
5. Для общего отключения: `PATCH /environments/{id}` с `{"enabled":false}` и текущим `If-Match`. Для одного флага изменить его `enabled` на false.

При 412 сначала прочитать свежую версию и решить, как совместить изменения; нельзя бесконечно повторять старый запрос. Без `If-Match` запись получает 428. История доступна через `/environments/{id}/audit?after=0&limit=50`.

## Ключи и SDK

SDK использует `Authorization: Bearer <sdk_key>`. У JWT и SDK-ключа разные области действия. `/sdk/snapshot` принимает `If-None-Match` и возвращает 304 только после проверки ключа. `/sdk/events` отдаёт поток ревизий. `POST /environments/{id}/rotate-key` с JWT и `If-Match` выдаёт новый ключ, прежний перестаёт работать. Seed при рестарте не возвращает отозванный demo-ключ и не сбрасывает выключенные флаги.

## Восстановление

```bash
make smoke
make recovery
docker compose ps
docker compose logs --tail=100 api
```

Smoke создаёт своё окружение и проверяет процентное включение, SSE и ротацию. В recovery используется `max_stale=2` и опрос каждые 0,2 секунды, чтобы быстро показать отказ при старом кеше. Скрипт временно убивает только API FlagHarbor и возвращает его в `finally`; PostgreSQL и настройки остаются на месте.

Если SDK не обновляется, проверить доступность `/health`, `last_error`, действительность ключа и свежесть `revision`. При сломанном SSE опрос продолжает работать. Если сервер доступен, но PostgreSQL не отвечает, HTTP-обновления тоже не продлевают кеш.

`docker compose down` сохраняет volume. Тесты используют отдельную временную базу `flagharbor_test`. Резервное копирование, централизованное хранение секретов, аудит действий операторов базы и проверка нагрузкой нескольких API-реплик требуют отдельной настройки.
