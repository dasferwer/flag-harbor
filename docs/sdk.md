# Контракт SDK

`FlagClient` живёт внутри одного async event loop. `start()` получает первый снимок и запускает фоновый опрос и, по умолчанию, SSE. Контекстный менеджер закрывает задачи и HTTP-клиент. Проверка `evaluate(key, context)` не блокируется на сетевом вводе-выводе. Для другого event loop или после `close()` нужен новый экземпляр.

## Порядок правил

1. Отключённое окружение возвращает `false` для всех флагов.
2. Отсутствующий или отключённый флаг возвращает `false`.
3. Явно исключённый пользователь получает `false`, даже если его организация разрешена.
4. Разрешённая организация или пересечение групп дают `true`.
5. Для остальных используется процент по идентификатору пользователя либо организации.

При `stickiness: organization` пользователи одной организации имеют общий bucket. Если организация не передана, процентное правило возвращает `false`. `rollout_bps: 100` означает 1%, `10000` — 100%. При росте процента сохраняется группа процентного правила; изменения allowlist, exclusions, stickiness или идентификаторов могут изменить результат независимо от процента.

`Context` содержит обязательный `user_id`, необязательный `organization_id` и список `groups`. Идентификаторы ограничены 128 символами, групп у запроса до 32. SDK-ключ и контекст следует использовать на доверенном backend: вызывающий код сам передаёт организацию и группы. Клиент браузера мог бы подставить чужие значения, поэтому это не механизм авторизации.

## Срок жизни снимка

Каждый успешный 200 или 304 обновляет время подтверждения на монотонных часах. Ошибка соединения, невалидный JSON, сменившийся environment_id или уменьшившаяся revision не заменяют снимок и не продлевают срок. Последняя ошибка видна в `last_error`, а решение из временно сохранённого кеша имеет `stale: true` после неудачного refresh.

Когда с успешной проверки прошло больше `max_stale`, результат — `false`, `reason: unavailable`, `stale: true`. То же поведение до первого успешного снимка. 401/403 и SSE `revoked` очищают кеш сразу. Кеш живёт в памяти, а после рестарта SDK должен снова связаться с сервером.

SSE ускоряет обновление, polling страхует разрывы. По умолчанию интервал опроса — 2 секунды, max_stale — 30 секунд. Успешный 304 означает, что версия снова подтверждена сервером; он закономерно продлевает жизнь кеша. Переопределяя интервалы, нужно оставить запас на HTTP-timeout и нагрузку, иначе SDK будет часто возвращать `false`.

`Evaluation` содержит `value`, `reason`, `revision`, необязательный `bucket` и `stale`. Номер версии помогает объяснить, почему два сервера с разной свежестью кеша временно дали разные ответы. HTTP-вариант `/sdk/evaluate` читает базу на каждый запрос и предназначен для сверки или клиентов без локального SDK.

Локальная проверка ищет флаг в списке до 100 элементов. Кеш не делится между экземплярами клиента. В текущем пакете нет синхронного lifecycle, дискового кеша и отдельного облегчённого SDK-wheel.
